# אפיון — סימולציית הישרדות דורית בתלת־ממד

## חזון ומושג הליבה

סימולציית חיים דורית: דמות אחת מתחילה בעמק ריק בלי כלים, בלי ידע ובלי בני אדם אחרים. היא שורדת, לומדת, מוצאת בן או בת זוג, מולידה, מזדקנת ומתה. הילדים ממשיכים, ולאורך דורות מה שהתחיל כאדם שמלקט פירות הופך לכפר.

השחקן אינו שולט בדמות. הדמות אוטונומית ומחליטה בעצמה לפי מצבה. השחקן צופה ומשפיע דרך שלושה ערוצים בלבד: רכישת פריטים בניקוד, שינוי עדיפויות, והכרעה בצמתים גורליים.

**מדד ההצלחה של המשחק הוא היומן.** השחקן נכנס פעמיים־שלוש ביום לשתי דקות, קורא מה קרה בהיעדרו, מגיב ויוצא. אם היומן משעמם — אין משחק, ושום גרפיקה לא תציל אותו. כל החלטת עיצוב במסמך הזה כפופה לשאלה הזו.

שלוש אמיתות שמגדירות את הפרויקט:

1. **הזמן זז תמיד**, גם כשהאפליקציה סגורה. חזרה אחרי לילה שינה = יומיים־שלושה של משחק שקרו בלעדיך.
2. **מוות הוא התקדמות, לא עונש.** הידע עובר לדור הבא, שמתחיל מנקודה טובה יותר.
3. **הסיפורים נולדים, לא נכתבים.** אין תסריטים מוכנים מראש — הדרמה נוצרת מהצטלבות של מערכות פשוטות.

## ארכיטקטורה

כלל הברזל של הפרויקט: **הסימולציה לא יודעת שקיים תלת־ממד.** שכבת ה־sim היא TypeScript טהור בלי React ובלי Three. שכבת ה־render קוראת state ומציירת אותו, ולא מחליטה דבר.

זו לא קפדנות לשם קפדנות. זה מה שמאפשר להריץ 200 ימי משחק בבדיקה אוטומטית תוך שנייה, ובמקביל לצפות בהם בתלת־ממד. כשה־AI יתנהג מוזר תדע מיד אם הבאג בהיגיון או בציור.

```
/src
  /sim          TypeScript טהור — אין import של react או three
    world.ts      tick(state, deltaMinutes) → state חדש
    needs.ts      דעיכת צרכים
    utility.ts    מנוע ההחלטות
    actions.ts    טבלת הפעולות והאפקטים שלהן
    knowledge.ts  עץ הידע והגילוי
    genetics.ts   תורשה, לידה, מוות
    events.ts     יצירת רשומות ליומן
    rng.ts        אקראיות עם seed — דטרמיניסטית
  /render       R3F — קורא בלבד
    Terrain.tsx   טריין flat-shaded
    Agent.tsx     דמות מונפשת
    Props.tsx     InstancedMesh לעצים, סלעים, מבנים
    Camera.tsx    מצלמה אורביטלית
  /ui           מסכי React רגילים — יומן, חנות, עץ משפחה
  /store        Zustand — גשר בין sim ל־render
```

**סטאק:** React + Vite + TypeScript, React Three Fiber עם drei, Zustand ל־state, Supabase לשמירה ולאימות. בהמשך Capacitor לאריזה כאפליקציה בלי לכתוב מחדש.

**החוזה בין השכבות:** ה־sim מייצר object אחד בשם `WorldState`. ה־render מקבל אותו ומצייר. אין callback מה־render אל ה־sim חוץ מפעולות שחקן מפורשות. אם אתה מוצא את עצמך כותב `if (mesh.position...)` בתוך `/sim` — עצור, משהו השתבש.

## מודל הזמן

יחס הבסיס: **שעת אמת אחת = יום משחק אחד.** יום משחק = 24 דקות אמת חלקי 24 שעות, כלומר דקת אמת = שעת משחק. חיים של 70 שנה = כ־70 ימי אמת, בערך חודשיים וחצי. זה מרגיש נכון: הדמות באמת מזדקנת מול העיניים שלך, ומוות באמת כואב.

| טווח | קצב | מה מתעדכן בו |
| --- | --- | --- |
| Tick | 6 דקות משחק | צרכים, תנועה, פעולה נוכחית |
| יום | שעה אמת | מזג אוויר, רשומת יומן מסכמת |
| עונה | ~15 שעות אמת | זמינות מזון, טמפרטורה, חקלאות |
| שנה | ~60 שעות אמת | גיל, פוריות, התיישנות מבנים |

### התקדמות במצב offline

אין סימולציה ברקע. שומרים `lastTick` ואת ה־seed. כשהשחקן חוזר:

1. מחשבים `elapsed = now - lastTick`.
2. מריצים את אותו `tick()` בלולאה מהירה, בלי רינדור, עם ה־seed השמור.
3. כל אירוע משמעותי נרשם ליומן.
4. מציגים את היומן לפני שמחזירים שליטה.

כיוון שה־RNG דטרמיניסטי עם seed, אותו state ואותו elapsed תמיד מייצרים את אותה תוצאה. זה קריטי — אפשר לשחזר באגים, ואי אפשר לרמות על ידי שינוי שעון המכשיר (משווים מול `now()` של Supabase).

**תקרת catch-up:** מקסימום 14 ימי משחק בחישוב מלא. מעבר לזה עוברים לחישוב מקוצר — אחד שמעדכן מצבים ומייצר אירועים מרכזיים בלבד, בלי סימולציה של כל tick. אחרת שחקן שחוזר אחרי חודש מקפיא את הדפדפן.

**האצה:** בתוך המשחק כפתור ×1 / ×5 / ×20 לצפייה. מעל ×5 האנימציות עוברות למצב מקוצר. זה גם כלי הפיתוח הכי חשוב שלך.

## סכמת ה־State

```ts
type WorldState = {
  seed: number;
  tick: number;              // מספר ה־tick מתחילת המשחק
  day: number;
  season: 'spring'|'summer'|'autumn'|'winter';
  weather: 'clear'|'rain'|'storm'|'snow'|'heat';

  agents: Record<AgentId, Agent>;
  playerAgentId: AgentId;    // במי צופים כרגע
  terrain: TerrainData;      // heightmap + ביומים, נוצר מה־seed
  resources: ResourceNode[]; // עצים, אבנים, פירות, מים
  structures: Structure[];   // מחסה, מדורה, מחסן, שדה
  items: Record<ItemId, Item>;

  knowledge: KnowledgeState; // מה השבט גילה עד כה
  journal: JournalEntry[];   // 200 אחרונות בזיכרון, השאר ב־Supabase
  playerPoints: number;
};

type Agent = {
  id: AgentId;
  name: string;
  sex: 'male' | 'female';
  birthDay: number;
  alive: boolean;
  deathCause?: string;

  needs: Record<NeedKey, number>;      // 0–100
  traits: Record<TraitKey, number>;    // 0–1, תורשתי
  skills: Record<SkillKey, number>;    // 0–100, נרכש אישית
  knownRecipes: Set<RecipeId>;         // ידע שהועבר

  health: number;
  pregnancy?: { conceivedDay: number; fatherId: AgentId };
  relations: Record<AgentId, Relation>;
  inventory: ItemId[];

  position: { x: number; z: number };
  currentAction: ActiveAction | null;
};

type Relation = {
  affection: number;   // -100 עד 100
  trust: number;
  kind: 'stranger'|'friend'|'partner'|'parent'|'child'|'sibling';
  lastInteractionDay: number;
};

type ActiveAction = {
  type: ActionId;
  targetId?: string;
  startedTick: number;
  durationTicks: number;
  progress: number;
};
```

**הערות תכנון:** ה־`terrain` לא נשמר — הוא נגזר מה־`seed` בכל טעינה, כך שרשומת השמירה נשארת קטנה. `journal` נשמר מלא ב־Supabase כי הוא התוכן של המשחק. `Set` צריך סריאליזציה ידנית ל־JSON.

## מנוע ההחלטות — Utility AI

בכל tick שבו הדמות פנויה, כל פעולה אפשרית מקבלת ציון. הדמות בוחרת את הגבוה. אין עץ החלטות ואין מכונת מצבים — וזה בדיוק מה שמייצר את הרגעים שמעניין לראות.

```ts
function score(action: Action, agent: Agent, world: WorldState): number {
  const base = action.appeal(agent, world);        // 0–1
  const feasible = action.feasibility(agent, world); // 0 או 1
  const traitMod = action.traitWeight(agent.traits); // 0.5–1.5
  const distance = distancePenalty(agent, action.target);
  const playerMod = world.playerPriorities[action.category] ?? 1;
  return base * feasible * traitMod * distance * playerMod;
}
```

המפתח הוא שצרכים נכנסים **בריבוע**. רעב של 50 לא מכתיב כלום, רעב של 90 מכתיב הכל. זה מייצר דמות שמתנהלת רגוע ואז נכנסת לפאניקה — בדיוק כמו בן אדם.

| פעולה | נוסחת appeal |
| --- | --- |
| לאכול | `(hunger/100)² × foodAvailable` |
| לשתות | `(thirst/100)² × 1.3` |
| לישון | `(fatigue/100)² × nightBonus` |
| להתחמם | `(cold/100)² × hasFire` |
| ללקט | `(1 - foodStock/10) × 0.6` |
| לבנות מחסה | `(1 - hasShelter) × weatherThreat` |
| לחזר | `(loneliness/100) × fertility × affection` |
| לשחק עם ילד | `childNeed × affection × 0.8` |
| להתנסות | `curiosity × (needsMet ? 1 : 0.1)` |

השורה האחרונה חשובה: **גילוי טכנולוגי קורה רק כשכל הצרכים מסופקים.** זו הדינמיקה המרכזית של המשחק כולו — הישרדות בקושי משמעה קיפאון, ועודף משמעו התקדמות. זה גם מה שהופך את הניקוד של השחקן למשמעותי: קניית מזון לא רק מונעת רעב, היא **קונה זמן פנוי שבו הדמות ממציאה דברים**.

### מנגנון ההשפעה של השחקן

שלושה ערוצים בלבד, כולם עקיפים:

1. **עדיפויות** — סליידרים לקטגוריות (הישרדות / חברה / מחקר / בנייה) שמכפילים את `playerMod`. מקסימום ×2, כדי שלא יהפוך לשליטה ישירה.
2. **פריטים** — הכנסת אובייקט לעולם משנה את ה־feasibility של פעולות. גרזן פותח כריתת עצים ביעילות כפולה.
3. **צמתים** — כשהדמות מתלבטת בין שתי אפשרויות בפער ציון קטן מ־10%, מגיעה התראה לשחקן. כך הוא מכריע בלי לשלוט.

| --- | --- | --- | --- |
| צמא | 100 | נזק 15 בריאות ליום | הכי דחוף |
| רעב | 45 | נזק 8 בריאות ליום | |
| עייפות | 60 | קריסה, שינה כפויה | מתאפס בשינה |
| חום גוף | תלוי עונה | נזק 10 ליום | חורף מכפיל ב־3 |

### בריאות ומוות

בריאות היא המשאב האמיתי. היא יורדת מצרכים לא מסופקים, פציעות, מחלות וזקנה, ועולה לאט כשהכל מסופק. אין בר בריאות במסך הראשי — רואים את זה בהליכה של הדמות, בצבע העור, בקצב.

סיבות מוות אפשריות: רעב, צמא, קפיאה, מחלה, פציעה בעבודה, טריפה, סיבוכי לידה, זקנה. תוחלת חיים בסיסית 65 שנה בתנאים טובים, יורדת ל־35 בתנאי מצוקה מתמשכת.

**משבר** הוא מצב שבו בריאות יורדת מתחת ל־30. אז, ורק אז, מופיעה התראה דחופה לשחקן והוא יכול להוציא ניקוד על הצלה. זה הרגע שמחזיר אותו לאפליקציה, ולכן חייב להיות נדיר: לא יותר ממשבר אחד לכמה ימי אמת, אחרת זה הופך למטרד והשחקן מכבה התראות.

### עונות

העונה היא לחץ ההישרדות המרכזי. קיץ = שפע ולחץ חום. סתיו = חלון האגירה. חורף = אין לקט, חום גוף דועך פי שלושה, ומי שלא אגר מת. אביב = לידות. מחזור של ארבע עונות = שנת משחק = כ־60 שעות אמת.

החורף הראשון הוא מבחן האמת של הגרסה הראשונה. אם דמות עם AI סביר שורדת אותו בלי התערבות, ודמות מוזנחת מתה — האיזון עובד.

## עץ הידע הדורי

זו המערכת שמייחדת את המשחק, ולכן היא הכי חשובה לבנות נכון.

**ההפרדה המרכזית: ידע נשמר בין דורות, כישורים לא.**

- **ידע** (`knownRecipes`) הוא ברמת השבט. ברגע שמישהו גילה אש, כל הצאצאים נולדים עם הידע שאש אפשרית ואיך מכינים אותה.
- **כישור** (`skills`) הוא אישי ומתאפס בכל דור. הבן יודע *שאפשר* להדליק אש, אבל האצבעות שלו עוד לא יודעות. הוא מתחיל מכישור 0 וצריך לתרגל — רק הרבה יותר מהר ממי שגילה מאפס.

זה מה שהופך מוות מעונש להתקדמות, ומייצר את קשת הסיפור מ"בלי כלום" ל"כפר" בלי שתכתוב אותה.

### מנגנון הגילוי

גילוי אינו מיידי. פעולת "התנסות" מצטברת לנקודות מחקר בקטגוריה, והטכנולוגיה נפתחת כשמגיעים לסף:

```ts
function attemptDiscovery(agent, world) {
  const candidates = availableTechs(world.knowledge);
  for (const tech of candidates) {
    if (!tech.prerequisitesMet(world)) continue;
    const rate = agent.traits.curiosity * agent.skills[tech.domain] * 0.01;
    world.knowledge.progress[tech.id] += rate;
    if (world.knowledge.progress[tech.id] >= tech.cost) {
      unlock(tech, world);
      journal.add('discovery', { tech, by: agent.id });
    }
  }
}
```

גילוי דורש גם **טריגר סביבתי**: אש נפתחת רק אחרי שהדמות חוותה סערת ברקים או שרפה טבעית. חקלאות רק אחרי שראתה זרעים נובטים ליד מקום אשפה. זה הופך כל גילוי לסיפור ביומן במקום לשורה בעץ טכנולוגיות.

### עידנים

| עידן | טכנולוגיות מרכזיות | דורות משוער |
| --- | --- | --- |
| לקט | לקט, כלי אבן, מחסה זמני | 1 |
| אש | אש, בישול, חימום, חנית | 1–2 |
| ציד ואגירה | ציד, עיבוד עורות, מחסן, שימור | 2–3 |
| יישוב | בקתה, חקלאות, ביות חיות, קדרות | 3–5 |
| מלאכה | אריגה, נגרות, מחרשה, גלגל | 5–7 |
| מתכת | כור, נחושת, ברונזה, כלי מתכת | 7–10 |
| קהילה | באר, טחנה, בית ספר, מסחר | 10+ |

העידנים הראשונים צריכים להיות מהירים — דור אחד־שניים כל אחד. אם הדמות הראשונה לא מגלה אש, אין למשחק קשת. מהעידן הרביעי והלאה אפשר להאט משמעותית.

**"בית ספר"** הוא נקודת מפנה שכדאי לתכנן אליה: מבנה שמעלה את מקדם העברת הידע, כך שהדור הבא מתחיל עם כישורים חלקיים ולא מאפס. זה השינוי שהופך שבט לציוויליזציה.

## דורות

### הבעיה של הדמות הראשונה

אדם אחד בעמק ריק לא יכול להוליד. צריך פתרון שלא ירגיש מלאכותי. שלוש אפשרויות, לפי סדר העדפה:

1. **נווד** — אחרי כ־20 יום, אם הדמות שרדה והקימה מחסה, עובר בעמק נווד מהמין השני. אם התנאים טובים הוא נשאר. זה הופך את השרידות הראשונית לתנאי לזוגיות, וזה מספר סיפור.
2. **ניצול** — דמות נוספת נמצאת פצועה ליד הנהר ביום אקראי בטווח 15–30.
3. **רכישה בניקוד** — פחות אלגנטי, אבל שסתום ביטחון אם השחקן תקוע.

ההמלצה: נווד כברירת מחדל, ניצול כאירוע אקראי שני, רכישה רק אחרי 40 יום ללא בן זוג.

### חיזור וזוגיות

מערכת יחסים מתפתחת מ־`affection` שעולה מאינטראקציות חיוביות: אכילה משותפת, מתנות, עזרה בעבודה, מוזיקה. ב־affection מעל 70 ושני הצדדים בגיל פוריות — נוצר זוג. זוגיות אינה נצחית: affection דועך בלי אינטראקציה, ובערכים שליליים ממושכים יש פרידה. זה מייצר דרמה אמיתית, במיוחד בשבט גדול.

### רבייה ותורשה

היריון 9 חודשי משחק (~11 שעות אמת). לידה נושאת סיכון: 5% תמותת אם בתנאים גרועים, 1% בתנאים טובים.

```ts
function inherit(mother: Agent, father: Agent, rng: RNG): Traits {
  const child = {} as Traits;
  for (const key of TRAIT_KEYS) {
    const avg = (mother.traits[key] + father.traits[key]) / 2;
    const mutation = (rng.next() - 0.5) * 0.3;  // ±15% וריאציה
    child[key] = clamp(avg + mutation, 0, 1);
  }
  return child;
}
```

תכונות מוצעות: `curiosity`, `diligence`, `sociability`, `courage`, `temper`, `constitution`. ±15% מוטציה זה המספר החשוב — מספיק כדי שייוולד נכד עצלן להורים חרוצים, לא מספיק כדי שהתורשה תיראה אקראית.

### ילדות

| גיל | מצב |
| --- | --- |
| 0–3 | תלוי לגמרי, צורך טיפול, לא פועל |
| 4–8 | משחק, לומד בצפייה, כישורים עולים לאט |
| 9–14 | עוזר בעבודות, מקבל ידע מההורים |
| 15+ | בוגר מלא, יכול לעזוב, להזדווג, לגלות |

רגע העברת הידע ב־9–14 הוא לב המערכת. אם ההורה מת לפני שהילד הגיע לגיל 9, **חלק מהידע הולך לאיבוד** — הדמות ידעה איך, אבל לא הספיקה ללמד. זה מייצר את אחד הרגעים החזקים ביומן, וגם לחץ אמיתי לשמור על ההורים בחיים.

### מעבר שליטה

כשהדמות הנצפית מתה, המצלמה עוברת לצאצא הבוגר הקרוב ביותר. אם אין צאצא בוגר אבל יש ילדים — עוברים אליהם והישרדותם היא אתגר בפני עצמו. אם כולם מתו, זה **סוף המשחק**: מסך סיכום שושלת עם כל הדורות, הגילויים והסיפור, ואפשרות להתחיל עמק חדש עם בונוס קטן לפי ההישגים.

## כלכלת הניקוד

יש שתי כלכלות נפרדות, וההפרדה ביניהן חייבת להיות חדה מהיום הראשון.

| | כלכלת הדמות | ניקוד השחקן |
| --- | --- | --- |
| שייך ל | העולם | לשחקן, חוצה דורות |
| מקור | עבודה, מסחר, אגירה | צפייה, הישגים, אירועים |
| קונה | אוכל, כלים, חומרים | הזדמנויות והתערבויות |
| נשמר במוות | חלקית (ירושה) | במלואו |

**הכלל:** ניקוד לא קונה לחם. ניקוד קונה **הזדמנויות**. אם השחקן יכול לקנות אוכל ישירות, כל מערכת ההישרדות מתמוטטת והמשחק הופך לכפתור.

### איך משיגים ניקוד

- כניסה יומית וצפייה פעילה (מעט — לא רוצים לתגמל בהייה)
- הישגים: גילוי ראשון, דור חדש, שרידת חורף, מבנה ראשון
- החלטה נכונה בצומת שהוצג לשחקן
- אתגרים יומיים ("שרוד את היום בלי לאבד בריאות")

### מה קונים

| פריט | עלות משוערת | אפקט |
| --- | --- | --- |
| חבילת זרעים | 50 | פותחת ניסוי חקלאות |
| כלי מתנה | 120 | מדלג על תרגול כישור |
| ברק מכוון | 200 | טריגר סביבתי לגילוי אש |
| רפואה | 300 | מציל ממשבר בריאות |
| נווד עובר | 400 | מביא בן/בת זוג |
| דחיפת השראה | 150 | ×3 לקצב מחקר ליום |
| שם לילד | 10 | קוסמטי |

**אין קנייה חוזרת של הצלה.** רפואה זמינה פעם אחת לכל דמות. אחרת מוות מפסיק להיות אמיתי, ואיתו נעלמת כל הדרמה.

**על מונטיזציה:** אם תרצה להכניס אותה בהמשך, הדרך היחידה שלא הורסת את המשחק היא מכירת ניקוד או האצת זמן — לא מכירת הצלות. מכירת הצלה ממוות היא בדיוק הדבר שהופך משחקים כאלה לזולים.

## מערכת היומן

זה התוכן האמיתי של המשחק. הכל השאר הוא תשתית שמייצרת אותו.

```ts
type JournalEntry = {
  day: number;
  hour: number;
  kind: 'need'|'social'|'discovery'|'birth'|'death'|'danger'|'build'|'mood';
  weight: 1 | 2 | 3;        // 3 = חייב להופיע בסיכום
  agentId: AgentId;
  data: Record<string, unknown>;
  text: string;             // מיוצר מתבנית + נתונים
};
```

### כתיבה

כל אירוע נבחר מבנק תבניות לפי `kind` ומצב הדמות. אותו אירוע נכתב אחרת כשהדמות עייפה, מאוהבת או מפוחדת. זה זול לבנות ומשנה לגמרי את התחושה:

- `"נועה מצאה גוש פירות ליד הנחל."`
- `"נועה, רעבה זה יומיים, נפלה על גוש פירות ליד הנחל ואכלה עומדת."`

עשרים תבניות לכל סוג אירוע מספיקות בהחלט להתחלה. **מומלץ מאוד להריץ את התבניות דרך LLM פעם אחת בזמן פיתוח** כדי לייצר מהן מאות וריאציות — ואז לשמור אותן כקבצי JSON סטטיים. בזמן ריצה לא קוראים ל־API: זה יקר, איטי ולא דטרמיניסטי.

### תצוגה

מסך הפתיחה כשחוזרים אחרי היעדרות הוא **המסך החשוב ביותר במשחק**, ולכן צריך להשקיע בו:

1. כותרת: כמה זמן עבר במונחי משחק ("עברו 3 ימים ו־7 שעות")
2. 3–5 אירועים בעלי weight 3, בעיצוב יומן אישי
3. מצב נוכחי של הדמות בשורה אחת
4. אם יש משבר פתוח — קודם כל הוא
5. כפתור "קרא הכל" ליומן המלא

### דף שושלת

בהמשך שווה לשקול ציר זמן של כל הדורות עם הרגעים הגדולים — מי גילה מה, מי נולד למי, מי מת ואיך. זה הפריט שאנשים משתפים, וזו דרך הצמיחה הזולה ביותר שיש למשחק כזה.

## שכבת הגרפיקה

סגנון: low-poly סטייליזד, פרופורציות מעט chibi (ראש גדול יחסית, פנים מינימליסטיות). הסיבה אינה אסתטית אלא מעשית — ריג הומנואידי סטנדרטי מאפשר למשוך אנימציות מוכנות מ־Mixamo, וזה חוסך את החלק שהורג פרויקטים כאלה. על מסך טלפון, צורה קריאה מנצחת טקסטורה מפורטת.

### החלטות רינדור

| נושא | החלטה | סיבה |
| --- | --- | --- |
| מצלמה | אורביטלית מלמעלה־הצידה, זום מוגבל, בלי סיבוב חופשי | זול, קל לביים, מרגיש כמו משחק ניהול |
| טריין | flat-shaded מ־simplex noise, ~60 יחידות רשת | נראה מכוון ולא עני |
| צמחייה | InstancedMesh, 3 סוגי עצים × 3 גדלים | מאות אובייקטים ב־draw call אחד |
| דמויות | ריג אחד, גיל ומגדר = סקייל והחלפת mesh | ריג שני = חודש עבודה |
| תאורה | directional אחת + ambient, צללים רק מהדמויות | צללים מלאים הורגים מובייל |
| שמיים | gradient shader עם מחזור יום־לילה | זול ומאוד אפקטיבי |
| LOD | דמויות מעבר ל־40 יחידות = impostor | |

### עקרונות ביצועים

- **אל תאנפש דמויות מחוץ למסך.** רק ה־state שלהן מתעדכן, ה־mesh קפוא.
- תקציב יעד: 60fps בדסקטופ, 30fps במובייל בינוני, עם 20 דמויות ו־400 אובייקטים.
- כל חומרי המשחק בטקסטורת atlas אחת. אידיאלית — vertex colors בלבד, בלי טקסטורות.
- מודלים דרך `useGLTF` עם Draco compression.

### שלב ה־placeholder

גרפיקה מהיום הראשון, אבל לא מודלים מהיום הראשון: קפסולה = בן אדם, קובייה חומה = עץ, מישור כחול = מים. הכל זז, הכל חי, הכל קריא. את המודלים האמיתיים מחליפים בחודש השלישי בלי לגעת בשורת לוגיקה אחת — זו כל הנקודה בהפרדת sim/render.

### אנימציות נדרשות למינימום

idle · הליכה · ריצה · עבודה (כללי) · אכילה · שינה · אינטראקציה חברתית · קריסה. שמונה קליפים. הכל אפשר למשוך מ־Mixamo על ריג הומנואידי סטנדרטי, עם blending בין מצבים.

## מפת שלבים

כל אבן דרך היא משהו שאפשר להריץ ולראות. אין שלב שהתוצר שלו הוא "תשתית".

### שלב 0 — הקפסולה החיה (1–2 שבועות)

טריין פרוצדורלי מ־seed, קפסולה אחת שהולכת עליו, שלושה צרכים (רעב, צמא, עייפות), ארבע פעולות, Utility AI בסיסי, מחזור יום־לילה, ושמירה עם התקדמות offline. **תנאי המעבר:** אתה חוזר אחרי שעתיים והקפסולה במקום אחר, עם מצב שונה, ואתה מבין למה.

### שלב 1 — הישרדות אמיתית (3–4 שבועות)

כל שמונת הצרכים, עונות, מזג אוויר, בריאות ומוות, לקט ובנייה, משאבים בעולם, מערכת היומן. **תנאי המעבר:** דמות מוזנחת מתה בחורף הראשון, ודמות עם AI סביר שורדת אותו.

### שלב 2 — ידע (2–3 שבועות)

עץ הידע, פעולת התנסות, טריגרים סביבתיים, שני העידנים הראשונים עד אש ובישול. **תנאי המעבר:** הדמות מגלה אש לבד, בלי שהתערבת, והיומן מספר על זה טוב.

### שלב 3 — השני (2–3 שבועות)

אירוע הנווד, מערכת יחסים, חיזור, זוגיות, שתי דמויות שפועלות בעולם אחד. **תנאי המעבר:** שתי דמויות מתאמות ביניהן ושורדות טוב יותר משאחת.

### שלב 4 — דורות (3–4 שבועות)

היריון, לידה, תורשה, ילדות, העברת ידע, מעבר שליטה במוות, עץ משפחה. **תנאי המעבר:** הרצת 5 דורות בהאצה ×20 בלי קריסה, ועץ המשפחה נראה הגיוני.

### שלב 5 — השחקן (2 שבועות)

ניקוד, חנות, עדיפויות, צמתים, התראות, מסך חזרה. **תנאי המעבר:** משחק שאפשר לתת למישהו אחר בלי הסבר.

### שלב 6 — הגרפיקה האמיתית (4–6 שבועות)

החלפת placeholders במודלים, אנימציות Mixamo, תאורה, חלקיקים, סאונד, ליטוש UI.

### שלב 7 — הרחבה (פתוח)

עידנים 5–7, מבנים מורכבים, ביות חיות, מסחר, אירועי שבט, דף שושלת לשיתוף.

**סך הכל לגרסה משחקת מלאה: כ־4–5 חודשים בקצב תחביב.** שלבים 0–2 הם המבחן האמיתי; אם אחרי שישה שבועות היומן לא מעניין אותך, עצור וחשב מחדש לפני שתשקיע בגרפיקה.

| ספירלת מוות | גבוהה | רצפת בריאות שמונעת נפילה חופשית, ותקופת חסד לדמות צעירה |

### הסיכון האמיתי

הסכנה הגדולה ביותר בפרויקט הזה איננה טכנית. היא **בניית מערכות מרהיבות שאף אחד לא רואה.** אפשר לבזבז חודש על גנטיקה מתוחכמת, ואם היומן לא אומר "הבן ירש את העקשנות של אביו", השחקן לעולם לא יידע שהיא קיימת.

כלל עבודה שמגן מפני זה: **כל מערכת חדשה מגיעה עם רשומות היומן שלה באותו commit.** אם אתה לא יודע איך מערכת תיראה ביומן — היא עוד לא מוכנה להיכתב.
